# ML-сервис триажа симптомов (Python, отдельно от C# бэка)
Тестовый вариант
Обученная модель, которая по свободному тексту жалобы пациента предсказывает
вероятный диагноз, специалиста и срочность. Работает как отдельный HTTP-сервис,
вызывается из C# бэкенда.

## Результат обучения

- **Датасет**: `Symptom2Disease.csv` — 1200 жалоб, 24 класса по 50. 47 жалоб — точные дубликаты,
  после их удаления остаётся 1153.
- **Модель**: TF-IDF (слова 1–2-граммы + символы 2–5-граммы) + калиброванный LinearSVC.
- **Оценка**: групповая 5-кратная кросс-валидация — почти одинаковые жалобы (сходство ≥ 0.8)
  всегда в одном фолде, чтобы не было утечки между train и test.
- **Accuracy**: **97.9 ± 0.6%** (word+char). Исходная версия только на словах: 97.0 ± 0.9%
  (на одном разбиении 80/20 было 96.3%).

| Проверка | Только слова | Слова + символы |
|---|---|---|
| Точность на датасете | 97.0% | 98.2% |
| 20% опечаток в тексте | 68.3% | 90.6% |
| Разговорные жалобы (96 шт., англ.) | 45.8% | 46.9% |
| Жалобы из другого датасета (1813 шт.) | 26.4% | 30.2% |

**Главный вывод**: на «книжных» жалобах из датасета модель почти идеальна, но на жалобах,
написанных по-другому, ошибается в большинстве случаев — и при этом часто остаётся уверенной.
Поэтому в сервисе два защитных флага (см. ниже), и **без проверки врачом ответ пациенту
показывать нельзя**.

## Защита от ошибок: три проверки

1. **`is_low_confidence`** — уверенность модели ниже 0.5.
2. **`is_out_of_distribution`** — жалоба не похожа на обучающие (символьное сходство с ближайшей
   обучающей жалобой ниже порога; порог подбирается при обучении так, чтобы отсеивать
   только 5% «своих» жалоб).

3. **`red_flags`** — правила опасных симптомов (`src/red_flags.py`): боль в груди, одышка,
   кровь при кашле или рвоте, отёк губ/горла, спутанность сознания и т.д. Если правило сработало,
   срочность поднимается (`urgency`) независимо от диагноза модели; исходная срочность модели —
   в `model_urgency`. **Список черновой, должен быть проверен врачом.**

Итоговый флаг **`needs_doctor_review` = любая из трёх проверок**. Если он `true`, C#-бэкенд не показывает
диагноз, а направляет к врачу.

Что даёт второй флаг (эксперимент `experiments/e6_ood_detector.py`):

| | Только порог уверенности | Уверенность + сходство |
|---|---|---|
| Свои жалобы: отвечено / точность | 95.7% / 99.5% | 92.2% / 99.7% |
| Чужие жалобы: пропущено | 35.5% | 6.2% |
| Чужие жалобы: занижена срочность (и пропущено) | 8.7% | 1.5% |

Что дают красные флаги (эксперимент `experiments/e8_red_flags.py`, модель word+char):

| | Свои жалобы | Чужие жалобы (1813) |
|---|---|---|
| Экстренные случаи распознаны как экстренные | 97.2% → 97.2% | **0% → 94.8%** |
| Занижена срочность | 0.5% → 0.5% | **23.6% → 10.1%** |
| Завышена срочность (лишняя тревога) | 0.9% → 9.5% | 15.9% → 32.7% |

То есть флаги почти вдвое снижают опасные ошибки (заниженную срочность), а платой за это
становятся лишние срочные направления — ошибка в безопасную сторону.

В ответе также есть `top_candidates` — 3 наиболее вероятных диагноза с вероятностями, для врача.

Цена: на разговорных жалобах сервис отвечает сам только примерно в 12% случаев, остальные
уходят к врачу. Это безопасно, но показывает, что для реальной пользы нужны реальные жалобы
пациентов для дообучения (логи `MLPredictions` + разметка врачом).

## Запуск

### 1. Установить зависимости

```bash
cd MED.ML-main
pip install -r requirements.txt
```

### 2. Обучить модель

```bash
cd training
python train_model.py --data ../data/Symptom2Disease.csv --output ../model
# другие признаки: --features word | char | word+char (по умолчанию)
```

### 3. Запустить сервис

```bash
cd src
uvicorn main:app --host 0.0.0.0 --port 8001
```

### 4. Проверить

```bash
curl -X POST http://localhost:8001/predict \
  -H "Content-Type: application/json" \
  -d '{"symptoms_text": "red itchy rash with dry scaly patches on elbows and knees"}'
```

Ответ:
```json
{
  "predicted_disease": "Psoriasis",
  "specialist": "дерматолог",
  "urgency": "routine",
  "model_urgency": "routine",
  "confidence_score": 0.81,
  "is_low_confidence": false,
  "similarity_score": 0.73,
  "is_out_of_distribution": false,
  "red_flags": [],
  "needs_doctor_review": false,
  "top_candidates": [
    {"disease": "Psoriasis", "specialist": "дерматолог", "probability": 0.81},
    {"disease": "Fungal infection", "specialist": "дерматолог", "probability": 0.04},
    {"disease": "Impetigo", "specialist": "дерматолог", "probability": 0.03}
  ],
  "translated_text": "red itchy rash with dry scaly patches on elbows and knees",
  "model_type": "symptom_triage_v2"
}
```

## Порог уверенности

В `main.py` задан `LOW_CONFIDENCE_THRESHOLD = 0.5`. Если `confidence_score` ниже
порога, ответ помечается `is_low_confidence: true` — такие случаи ваш C# бэкенд
должен **не отдавать пациенту как финальную рекомендацию**, а либо направлять
к врачу напрямую, либо показывать более общий, безопасный ответ ("обратитесь
к терапевту для уточнения").

Порог 0.5 — начальное значение для демо. Его стоит подбирать по факту (можно
проанализировать распределение confidence_score на реальных жалобах и выбрать
порог, который даёт приемлемый баланс между точностью и количеством эскалаций).

## Мультиязычность (ru / uz / en)

Модель обучена только на английских текстах — переучивать её на 3 языках
означало бы искать/размечать датасеты на русском и узбекском, которых нет.
Вместо этого используется **перевод перед классификацией**:

```
жалоба на ru/uz → deep-translator (Google Translate) → English → модель → диагноз
                                                            │
                                          specialist_mapping.py возвращает
                                          название специалиста на ТОМ ЖЕ языке,
                                          на котором пришла жалоба
```

**Библиотека**: `deep-translator` — бесплатная обёртка над Google Translate,
не требует API-ключа или регистрации, нужен только интернет на машине,
где крутится сервис.

**Ограничение, которое стоит знать**: бесплатный Google Translate (через эту
библиотеку) может быть менее точным на специфических медицинских терминах,
чем перевод через LLM, и теоретически может со временем измениться/сломаться,
так как это не официальный платный API, а обёртка над публичным сервисом.
Для демо и учебного проекта это приемлемо; если понадобится более надёжный
и предсказуемый перевод в будущем — можно заменить на платный Google Cloud
Translation API или Yandex Translate API, не переписывая остальной код
(вся логика вынесена в `translate_to_english()` в `translation.py`).

**Настройка**: ничего не нужно — просто установлен пакет из `requirements.txt`,
никаких ключей или переменных окружения:
```bash
uvicorn main:app --host 0.0.0.0 --port 8001
```

**Запрос принимает поле `language`:**
```json
{ "symptoms_text": "у меня зудящая сыпь на локтях и коленях", "language": "ru" }
```

**Ответ включает `translated_text`** — что реально ушло в модель, полезно
для отладки и для проверки качества перевода:
```json
{
  "predicted_disease": "Psoriasis",
  "specialist": "дерматолог",
  "urgency": "routine",
  "confidence_score": 0.68,
  "is_low_confidence": false,
  "translated_text": "I have an itchy rash on my elbows and knees",
  "model_type": "symptom_triage_v2"
}
```

Если `language: "en"` — перевод пропускается вообще (быстрее, не тратит время
на сетевой запрос).

**Названия специалистов на 3 языках хранятся готовым словарём**
(`specialist_mapping.py`), не переводятся налету — так исключается риск,
что перевод даст разные варианты названия одной и той же специальности
в разных запросах.

**Что дополнительно стоит проверить перед реальным использованием**:
качество перевода узбекских медицинских формулировок через бесплатный
Google Translate — стоит протестировать на реальных примерах жалоб пациентов,
и при необходимости перейти на более точный (платный) переводчик.

## Интеграция с C# и MLPredictions

`csharp-client/` — готовые классы:

- **`MlTriageClient.cs`** — вызывает Python-сервис через HTTP, парсит ответ
- **`MlPredictionLogger.cs`** — пишет результат в вашу таблицу `MLPredictions`
  (Id, ModelType, EntityType, EntityId, InputSnapshot, PredictedValue,
  ConfidenceScore, CreatedAt, Feedback)

Подключение в `Program.cs` вашего основного бэка:
```csharp
builder.Services.AddHttpClient<MlTriageClient>();
builder.Services.AddScoped<MlPredictionLogger>();
```

Конфиг:
```json
{
  "MlService": {
    "BaseUrl": "http://localhost:8001"
  }
}
```

Пример использования в контроллере:
```csharp
var prediction = await _mlTriageClient.PredictAsync(symptomsText, language); // "ru" | "uz" | "en"
var predictionId = await _mlPredictionLogger.LogPredictionAsync(
    "consultation", consultationId, symptomsText, prediction);

if (prediction.NeedsDoctorReview)
{
    // направить к врачу напрямую, не показывать диагноз как окончательный
}
```

## Что нужно доделать перед реальным использованием

1. **`specialist_mapping.py` не проверен врачом** — это моя черновая раскладка
   24 диагнозов по специалистам на основе общей логики, не медицинская экспертиза
2. **Собрать реальные жалобы** — на разговорных и «чужих» жалобах точность 26–47%
   (см. таблицу выше). Нужны реальные жалобы из логов `MLPredictions`, размеченные врачом,
   для дообучения
3. **Расширить набор диагнозов** — сейчас только 24 класса из Symptom2Disease.
   Датасет `Final_Augmented_dataset_Diseases_and_Symptoms.csv` (773 диагноза,
   377 бинарных признаков) можно использовать для расширения, но потребует
   отдельного шага — извлечения структурированных симптомов из текста жалобы
   (NER), это отдельная и более сложная задача, не входит в текущее демо
4. **Мультиязычность** — сейчас ru/uz переводятся на английский перед моделью.
   Качество этого шага проверяет `experiments/e7_multilingual.py`
5. **Проверить `red_flags.py` у врача** — правила сделаны по общим принципам
   неотложной помощи, их нужно дополнить и выверить

## Эксперименты для статьи (`experiments/`)

Датасеты положить в `data/` (или указать путь: `DATA_DIR=/путь python ...`). Запускать из `experiments/`:

| Скрипт | Что проверяет |
|---|---|
| `e1_leakage.py` | дубликаты и их влияние на точность (разные протоколы CV) |
| `e2_models_noise_calibration.py` | 7 моделей, устойчивость к опечаткам, калибровка, порог |
| `e5_ood_shift.py` | 1813 жалоб, собранных из второго датасета (сдвиг распределения) |
| `e6_ood_detector.py` | детектор незнакомых жалоб (запускать после e5) |
| `e7_multilingual.py` | весь конвейер на 96 разговорных жалобах en/ru/uz (нужен интернет) |
| `e8_red_flags.py` | правила красных флагов: заниженная и завышенная срочность (после e5) |
| `figs.py` | графики для статьи (после e2 и e5) |

Разговорные жалобы в `lay_complaints_en_ru_uz.py` составлены с помощью ИИ-ассистента
(параллельно на трёх языках), а не реальными пациентами. Это нужно указывать в статье.
